# 学习过程中提出的问题

以下根据本次实际讨论整理，保留容易混淆的地方。代码位置相对于本项目的 `code/`，行号按此版本核对。研究目标是从已采集 CSI 提取人体运动特征；本实验没有训练手势分类器。

## 1. Widar3.0 的文件已经有 CSI 了吗？第一步还是第二步从信号得到 CSI？

本次使用的 `.dat` 已包含采集时得到的 CSI 记录。采集先发生：发射器发送 Wi-Fi 数据包，接收机根据包中的已知训练信号估计信道，采集工具把 CSI、接收时间和相关设备信息保存到文件。

笔记第1步只是选择文件并启动程序；第2步读取、校正和整理已有 CSI，不从原始无线波形重新估计信道。`.dat` 也不是已经可以直接用于后续计算的 Excel 表，需要解码。

## 2. 为什么“装进数据包”，又说“按时间收下小信件”？

“小信件”是早先的比喻，容易把两种数据混在一起，应按真实顺序理解：收到无线数据包 → 接收机估计 CSI → 保存一条测量记录 → MATLAB 读取记录。不是发射器先把 CSI 装进无线数据包再发送。

Wi-Fi 帧含有帮助接收机同步和估计信道的已知训练信号，也可以承载实际通信数据。CSI 是接收端根据这些信号估计出的信道信息。`csi_tool_box/read_bf_file.m` 第13行打开日志，第47～53行读取记录，第67行调用 `read_bfee` 解析 CSI 记录。

## 3. 为什么摆成表格？表格怎么来的？

表格是方便计算的数字矩阵。一个包在这组数据中对应3根接收天线，每根30条子载波，共90个 CSI 复数值。每包放一行，天线和子载波按固定顺序放90列。

`csi_tool_box/csi_get_all.m` 第4行准备空矩阵，第16行把三根天线各30个值拼成一行，第19行把当前包写进第 `k` 行。接收机1的1479包得到 `1479×90`；其他接收机的包数不完全相同。

```matlab
% csi_get_all.m 第4行
cfr_array = zeros(length(csi_trace), 90);
% 第16行
csi = [csi_all(:,1); csi_all(:,2); csi_all(:, 3)].';
% 第19行
cfr_array(k,:) = csi;
```

沿一列往下读，始终是同一根天线、同一条子载波在不同包时刻的测量。这使滤波和频率分析有明确的时间顺序。`zeros` 只是提前分配位置，不是生成新的测量值。

## 4. 校正是什么？为什么与 RSSI 有关？

CSI 提供各天线和子载波的详细复数测量，RSSI 提供整体接收信号强弱。网卡报告的原始 CSI 数字并非直接采用实际接收功率刻度。工具用 RSSI、自动增益、背景噪声和量化误差估计，调整 CSI 的数值尺度；输出还按总噪声功率归一化。

`csi_get_all.m` 第10行调用 `get_scaled_csi`。`get_scaled_csi.m` 第10～14行根据 CSI 大小平方与 RSSI 功率的关系计算 `scale`，第34～40行考虑噪声并缩放。

```matlab
% get_scaled_csi.m 第10～14行
csi_sq = csi .* conj(csi);
csi_pwr = sum(csi_sq(:));
rssi_pwr = dbinv(get_total_rss(csi_st));
scale = rssi_pwr / (csi_pwr / 30);
% 第40行
ret = csi * sqrt(scale / total_noise_pwr);
```

`/30` 对子载波取平均，天线的功率贡献仍合计。RSSI 不是替代 CSI，而是给其整体尺度提供参照。一个包乘一个缩放系数，保持相位；不会产生新的包，也不等于全部去噪。

## 5. 时间戳是什么？“CSI + 包接收时间戳”不是已经变成表了吗？

CSI 已经排成表，时间戳是另外一列接收计时记录。接收机1得到 `cfr_array:1479×90` 和 `timestamp:1479×1`，按行一一对应。`+` 在笔记里表示“同时有这两份数据”，不是做加法。

`csi_get_all.m` 第18行记录时间戳，通常是设备微秒计时器的低位数值，不是日历时刻；完整时间处理还应考虑计数器回绕等情况。当前 DFS 代码用 `~` 忽略时间戳，直接假设1000包/秒。因此图轴标作 **Nominal time（名义时间）**。

```matlab
% csi_get_all.m 第18～19行
timestamp(k) = csi_entry.timestamp_low;
cfr_array(k,:) = csi;
% get_doppler_spectrum.m 第26行
[csi_data, ~] = csi_get_all(spth);
```

## 6. 文件名为什么不直接写好？代码为什么分散？

`get_doppler_spectrum.m` 第23～26行用循环把相同样本前缀与 `-r1.dat` 至 `-r6.dat` 拼接，方便处理6个接收机，不必复制6份算法。

读取和整理已集中在 `csi_get_all.m`；它调用 `read_bf_file` 解码、调用 `get_scaled_csi` 校正。上层脚本是调用这些函数，不是每个文件都重复实现读取。新增入口做一次检查，作者函数又读取一次，属于当前包装方式的重复读取，可以进一步重构。

## 7. 为什么3根天线都计算，却还要选参考天线？

第36～39行先比较3根天线，选幅度均值/标准差的平均比值较大的一根作参照。第41行把其30条子载波复制三遍。另两根天线各自与它比较，用相对相位减少两路共享的相位偏差。

参照只是一根比较基准，不是绝对正确的标准。这一段数据处理时 `idx` 固定，不会每个包都换；不同接收机或不同样本可以选择不同的参照。

## 8. 参考天线自己变了怎么办？不知道标准时间怎么消除共同误差？

不需要知道共同误差的数值。假设原相位20°和10°，设备给两路都加50°，测量成为70°和60°。相位差仍是10°：

$$
(20+50)-(10+50)=20-10.
$$

共同项相消，但没有把天线1的绝对相位恢复为20°。如果参考信号自身又变化，或者两路误差不同，就会影响结果。选幅度稳定的参照也不能保证其相位不动。后续滤波/PCA帮助处理某些干扰，并不保证消除这些残余误差。

## 9. 已经相对了，为什么还调整幅度？第6步又共轭相乘是做两次吗？

相位相减与幅度调整是不同事情。共轭乘积的角度是两路角度之差，但大小是两路大小的乘积：

$$
\arg(H_1H_2^*)=\arg H_1-\arg H_2,\qquad
|H_1H_2^*|=|H_1||H_2|.
$$

第44～55行先调整幅度：待处理幅度减去最小非零幅度 `alpha`，参考幅度加上较大的 `beta`，均保留相位。减基线可改变背景和变化的相对强度；加大参考幅度可减小其幅度波动的相对比例。这是经验处理，不是精确静态路径分离。

第59行再共轭相乘，只进行一次。之前讲第5步时提前介绍第6步，是解释准备工作的目的，并没有额外乘一次。第60行去掉参考与自身相乘的30列，留下60列。

## 10. CSI不是整个信道状态吗？为什么筛掉慢和快的变化，只关注人体？

CSI 确实包含多条传播路线、静态背景、运动和设备误差。本任务的目标是手势运动特征，所以有目的地提取运动相关部分，而不是完整保留、重建整个信道。

这里的快慢是共轭处理后信号随时间的变化频率，不直接等于人走路的快慢，也不是 Wi-Fi 的 GHz 载频。第8行 `uppe_stop=60`、第10行 `lowe_stop=2`，第11～12行设计低通/高通，第64～65行实际滤波。

很慢的分量可能含静态背景和缓慢漂移；很快的分量可能含高频噪声或任务范围外变化。真实运动也可能在这些范围，会被一起压低，所以2～60 Hz是作者对本任务的选择，有代价，不是“慢快的一定无用”。滤波也不自动识别人体、墙壁或其他运动物体。

## 11. PCA是什么？怎么把两根天线合成一条？权重为什么不同？

删掉参考后是两根天线各30条子载波记录，共60列，不是只有两列。PCA根据它们的变化关系计算组合系数，然后在每个时刻用60个系数加权组合成一个复数值。

$$
z[k]=\sum_{j=1}^{60}X[k,j]w_1[j].
$$

```matlab
% get_doppler_spectrum.m 第69～70行
pca_coef = pca(conj_mult);
conj_mult_pca = conj_mult * pca_coef(:,1);
```

它不把两段时间首尾拼接，也不打乱包顺序；`T×60`变为`T×1`。权重不必相同，因为各列变化幅度、相关性和噪声不同。第一主成分寻找最大方差方向，不代表权重大就更准确；噪声也可能影响结果。

## 12. PCA是不是生成最开始那张CSI折线图？

不是。`step1_csi_to_dfs.m` 第45行直接画接收机1校正后CSI矩阵第1列的幅度，对应第一根天线、第一条子载波：

```matlab
plot((0:size(csi_rx1,1)-1)/sample_rate_hz,abs(csi_rx1(:,1)));
```

这张图尚未经过后续共轭、滤波和PCA。虽然程序最后才显示它，展示的数据仍来自读取阶段。6路彩色DFS图才来自PCA之后的短时频谱分析。

## 13. 为什么逐小段看频率？原来有时间，傅里叶分析把时间变没了吗？

动作会随时间改变。对整段只计算一次功率频谱，回答“整段里各频率有多强”，不会直接列出它们什么时候出现。这里说的是查看整段的**功率频谱**；不能把这句话理解为“完整复数傅里叶变换不可逆”。

短时分析则反复计算：每次选原信号附近一段，算一份频谱，并保留窗口的中心位置。多份结果按中心位置排好，仍有时间轴，又有频率轴。不是把时间从有变无后再凭空造出来。

## 14. 到底怎么切小段？会不会把时间弄乱？

`get_doppler_spectrum.m` 第77～83行：

```matlab
time_instance = 1:length(conj_mult_pca);
window_size = round(samp_rate/4+1);
if(~mod(window_size,2))
    window_size = window_size + 1;
end
freq_time_prof_allfreq = tfrsp(conj_mult_pca, time_instance,...
    samp_rate, tftb_window(window_size, 'gauss'));
```

窗口是251点，中心两边各125点；采样率假设1000，所以完整窗口约0.25秒。`time_instance`依次为1、2、3……，每次中心移动1个点；窗口大量重叠，不是互不重叠地切成几块。

| 中心的名义时间，举例 | 使用的原信号范围 |
|---|---|
| 0.500秒 | 约0.375～0.625秒 |
| 0.501秒 | 约0.376～0.626秒 |
| 0.502秒 | 约0.377～0.627秒 |

`tftb/mfiles/tfrsp.m` 第83～88行按 `t(icol)`逐列处理，`x(ti+tau)`按原位置取值，结果写入第 `icol` 列。它不会把时间样本重新乱排。记录起止边缘没有完整251点时，只用有效部分并按相应窗能量归一化。

第89行对每列做FFT并取大小平方：

```matlab
tfr=abs(fft(tfr)).^2;
```

## 15. 标在0.5秒的频谱，是真正0.5秒那个瞬间吗？

它描述以0.5秒为中心、附近约0.25秒内的频率情况，不是无限短的一瞬间。时间标签来自原记录中的窗口位置，不是电脑计算频谱时的钟表时间。

另外，本代码忽略真实时间戳，按包序号/1000推算，所以图上是名义时间。窗口有时间范围，与时间轴没有用真实包间隔校正，是两件不同的事。高斯窗中间权重大，实际影响也不均匀。

## 16. 频谱快照到底是什么？为什么又变成一张张照片？

没有额外的拍照或再变换。一小段信号经短时分析得到的一份频率功率记录，就被叫作一份“频谱快照”。

一个接收机的一份快照是121个频率功率值，在DFS彩色图里占一列。6个接收机在同一索引处一起取出，则是 `6×121`。把1479份按时间排列，得到 `6×121×1479`。名称变化是在描述计算输出，不是又生成一种人体照片。

本代码取−60～60 Hz；原FFT频率排列是 `[0:60,-60:-1]`。`step1_csi_to_dfs.m` 第23～24行同时调整频率标签和DFS的第二维，时间第三维保持顺序不变。1 Hz格点间隔也不等于实际能分清相差1 Hz的两个分量。

## 17. 已经按小窗口处理了，为什么又每100张快照分段？为什么是100？

两个操作的对象不同：251点窗口对**信号**做时频分析；100快照分段对已经得到的**频谱列**求平均，再估计一次BVP。

`step2_dfs_to_bvp.m` 第23行设定 `seg_length=100`，第46行对连续100列的第三维求平均。100是沿用作者实现的参数，不是数学上只能选100。它减少短时频谱波动，也减少优化次数，但会压缩时间细节；选择其他长度，需要重新评估。

```matlab
target = mean(doppler_spectrum(:,:,(ii-1)*seg_length+1:ii*seg_length),3);
```

窗口中心每次移动约1毫秒，100个中心覆盖约0.1秒；绝不是100×0.25=25秒。由于这些频谱已各使用一个约0.25秒窗口，一组内部段还受约0.35秒原始信号范围影响，例如中心0.500～0.599秒对应约0.375～0.724秒。边缘段范围会截短。

1479个快照产生14个完整组，剩下79个舍弃。每组得到代表频谱 `6×121`，随后优化得到速度功率表 `20×20`。平均频谱不是直接变成人体图。

## 18. 为什么还要设备位置？CSI不带位置吗？

CSI的幅度和相位受位置影响，但没有直接提供人体的二维坐标字段。原信号也不是只含运动变化；其中有静态路径和其他因素。

代码需要另行输入发射器、接收机和人体位置及人体朝向。本次 `step2_dfs_to_bvp.m` 第16～20行使用作者示例布局；它们不是此次自动定位得到的。

```matlab
torso_pos = [1.365 0.455];
torso_orientation_deg = -90;
Tx_pos = [0 0];
Rx_pos = [0.455 -0.455; 1.365 -0.455; 2.0 0; ...
          -0.455 0.455; -0.455 1.365; 0 2.0];
```

论文还讨论了通过前置运动跟踪获得位置、朝向的办法；本实验没有复现自动定位/朝向估计模块。

## 19. 设备观察位置具体怎么算？

人体附近反射点移动时，Tx→人体和人体→Rx两段传播距离同时变化。`get_A_matrix.m` 第8～11行先算两段距离，再把两个单位方向向量相加，得到每路的几何系数 `A(r,:)`。

按照作者代码约定：

$$
f_r(\mathbf v)=\operatorname{round}\left(
\frac{A_{r,x}v_x+A_{r,y}v_y}{\lambda_{\mathrm{wave}}}\right).
$$

`get_velocity2doppler_mapping_matrix.m` 第21～22行实现它，第27～28行把该候选速度对应的频率格置1。其余格为0；超出频率范围的候选，作者代码用很大的值进行惩罚。几何按人体代表位置近似；整体正负号受相位/共轭和坐标约定影响，不能直接叫“正频率就是向前”。

## 20. 已经知道几何与速度映射，为什么还要反推？是不是反过来拍？

映射只是“假如按某种速度运动，各路应看到什么频率”的对应规则。它没有告诉我们人体实际采用了哪种速度，更没有给出每种速度有多少功率。

这里没有反过来拍摄。代码列出400种候选速度，把候选功率表 `P`按映射生成6路预测频谱，再与实际DFS比较，调整 `P`。这叫反推/反演：利用已知关系，从观测估计未知量。

$$
\widehat D_r[k]=\sum_{i,j}\mathrm{VDM}[i,j,r,k]P[i,j].
$$

`DVM_target_func.m` 第14～17行是从候选P预测DFS，第24～25行是与实测频谱比较。多种速度的贡献可能叠加到同一频率格，所以不是简单把一个Hz乘常数就得到完整二维速度分布。

## 21. 为什么速度方向要以人体自己为准？

人在房间里转身再做“向前推”，对房间而言方向变了，但相对于人自身仍是向前。用人体朝向作为正x方向，希望同一动作换朝向后有相近的特征，有利于跨位置、跨朝向识别。

先按场景坐标求速度功率，再调用 `get_rotated_spectrum` 转到人体坐标。第18～21行补成21×21，围绕零速度中心旋转，再裁回20×20。这里旋转的是速度分布，不是人体位置或照片。

## 22. 收敛了是不是完全正确？为什么与参考图不一致？

14段 `exit_flag=1` 表示求解器报告满足停止条件，不证明全局最优、唯一解或真实人体速度完全正确。原目标含EMD绝对值和L0计数，存在非光滑/不连续问题。

与包内候选参考对比，平均余弦相似度约0.615、重叠度约0.483，第13段几乎一致。对同一份实测DFS按官方EMD项核算，本次结果平均27.938，候选参考29.105。它们衡量拟合，而非动作识别准确率或人体速度真值误差。

候选参考前缀为 `user`，输入CSI前缀为 `userA`，原包未明确说明对应关系。数值证据支持接近的处理链，但样本身份及生成环境仍未最终确认。
