# 02 · PhotoRestore：照片清晰化工作台

上传低分辨率照片，通过 **ResShift 预训练扩散超分辨率模型**生成 4× 尺寸结果。支持本地账户注册/登录/退出、JPG/PNG/WebP、拖放上传、处理尺寸选择、增强混合程度、真实推理进度、取消、原图/普通插值对照、完整尺寸查看、PNG 与 JSON 报告下载。

**定位：已有预训练方法的 Web 工程应用，不是自行训练的新模型，也不是新的图像恢复算法。** 比较适合尝试增强低分辨率、压缩过的照片；严重失焦、运动模糊和已丢失的信息不保证恢复。新增人脸、文字和纹理细节可能偏离原图，不用于判断证件、车牌或证据内容。

## 使用方法

1. 注册或登录本地账户，然后上传一张低清照片，或选择猫咪、咖啡、人像示例。支持 PNG/JPEG/WebP，总请求上限 10 MB，图片上限 2000 万像素，长边至少 32 像素；不支持动画。
2. 默认选择“保留原图”，长边不超过 1280 像素的上传图片保持原始尺寸，分块进行 4× 重建。例如 1254×1254 输入仍为 1254×1254，输出 5016×5016。大图可能需要数分钟，且占用更多内存。超过上限会明确报错，不自动缩小。若需要更快处理，可主动选择 192、384 或 512 像素的“缩小预览”；此时会先等比缩小，再生成该处理尺寸的 4× 结果，可能损失细节。
3. 点击“开始清晰化”，等待本机实际推理。首次任务还需载入模型，可能比随后任务慢。进度基于实际完成的扩散采样步骤，不是预设动画。
4. 拖动对比滑块；可切换左侧为原图浏览器放大或普通双三次插值。右侧为本次生成的模型输出，不代表一定更清晰。可使用“并排看全图”查看同一部位，或使用“仅看输入／仅看模型输出”分别查看；滑块移到边缘时会隐藏不对应的标签。左侧“处理输入”在默认保留模式下与原始像素尺寸一致；仅在主动选择缩小预览时才是缩小后的输入。界面和报告标明实际尺寸。
5. 下载 PNG 与实验 JSON。上传实际照片没有清晰参考，**不计算 PSNR/SSIM，也不显示虚构的清晰度提升百分比**。

增强混合程度 100% 为模型输出；0% 为普通双三次插值。中间值是两者的像素混合，仍会运行模型，不代表某种恢复置信度。改变尺寸、种子、混合程度后，旧结果会明确标记，需重新运行才生效。

任务取消在当前模型步骤完成后响应。页面刷新后不会自动恢复任务，离开前请下载需要的图片。

## 实际结果

下面三张完整源图先缩小至长边最多 384，再取可被 4 整除的参考尺寸。输入由参考图进行 4× BICUBIC 缩小、半径 0.4 的高斯模糊、JPEG quality=45 / subsampling=2 压缩得到。统一随机种子 2026，模型 4 步，混合程度 100%。

| 示例 | 普通插值 PSNR ↑ | 模型 PSNR ↑ | 模型推理耗时 |
|---|---:|---:|---:|
| 猫咪 | 26.76 dB | 26.08 dB | 1.05 s |
| 咖啡 | 22.69 dB | 23.79 dB | 0.44 s |
| 人像 | 21.44 dB | 21.60 dB | 1.02 s |

数值为完整 RGB 图像、像素范围 [0,1] 上的全图 PSNR，不裁边。耗时在模型载入后统计，包含分块、去噪、解码和融合，不包含首次载入、上传与文件保存。当前登录后浏览器端真实上传测试：451×300 输入先缩小到 192×128，输出 768×512，2 个分块，模型推理约 3.50 s。同一上传在原尺寸模式下保持 451×300，输出 1804×1200，15 个分块，约 14.95 s。更大输入通常耗时更长，不能把小图耗时当成统一承诺。

**三例中模型有两例的 PSNR 高于插值，猫咪示例仍低于插值。** 模型可产生更鲜明的纹理，但不一定更接近参考图。这里是三张演示图、一个降质设置和一个种子，不是独立大规模测试集，不宣称普遍优于插值，也不根据结果挑选种子。

## 为什么示例好看，自己的图片不一定好

内置示例是清晰源图经过固定的缩小、轻度模糊和 JPEG 压缩生成的，不是真实失焦照片的代表性测试集。它们仍保留了可推断的结构和纹理，不能用于承诺任意上传图片都能恢复。

之前的上传流程默认把大图缩到长边 384 像素，造成额外的信息损失；小示例没有触发这一步，比较条件不一致。当前已取消默认缩小，改为保留原始尺寸分块处理（长边≤1280），预览缩小需要用户主动选择。原图超过保留模式上限时会报错，不静默回退到缩小模式。修正这一工程问题不等于解决严重失焦、运动模糊或不可逆信息丢失。

## 针对输出偏平滑的改进

默认模型已从旧版 15 步 v1 更新为官方 journal 版本的 4 步 v3，同时使用其匹配的网络源码、配置与噪声调度。新权重不是把旧模型简单改成少采样几步。代码仍严格检查所有权重键，兼容官方编译权重的 `_orig_mod.` 前缀。

实测半精度/全精度、复制/反射填充在猫咪案例上变化很小，因此没有把它们当作主要修复手段。新版在当前猫咪样例上生成了更明显的毛发纹理，但 PSNR 从旧版约 26.32 降到 26.08 dB；咖啡从 23.33 升至 23.79，人像从 20.76 升至 21.60。视觉纹理、参考误差与真实细节不是同一回事。

左至右：相同低清输入放大、旧版 v1、新版 v3。输入和种子固定，旧版使用之前的复制填充适配，新版使用对应 journal 源码和反射填充；这是实现版本对照，不是严格隔离单变量的模型排名。

![输入、旧版、新版同尺寸对照](results/quality-check/cat-v1-v3.png)

旧版原始输出、评估 JSON、权重来源与对照记录保存在 [quality-check](results/quality-check/)。旧版代码可从提交 `4e01f9a9d7905e9bbef1d218b00fcdd127124d12` 查看。E 盘旧版权重暂保留便于回退，新下载仅需新版清单中的两个权重。

滑动分割线可能让一边只剩背景，不能据此比较猫脸的清晰度。新增“并排看全图”会同时显示完整输入和完整输出，避免遮住主体再判断效果。模型仍不保证能修复严重失焦，也不以锐化滤镜替代模型结果。

## 技术实现与边界

- **前端**：原生 HTML/CSS/JavaScript，响应式布局、上传/拖放、滑块对比、对话框查看完整尺寸、下载。
- **后端**：Flask，单模型工作线程，最多 3 个在途任务。HTTP 请求提交任务后轮询真实状态，不在请求线程中长时间占用模型。
- **模型**：ResShift realSR ×4，官方 `s4_v3` 权重，4 步残差平移扩散，Swin U-Net 与 VQ autoencoder。
- **适配**：GPU 使用半精度的上游模型转换；VQ 单头注意力采用等价 PyTorch SDPA，含数值一致性测试。GPU 输入以 128×128 分块、32 像素重叠融合；CPU 使用 64×64 分块。边缘按官方配置优先反射填充，极窄图片不满足反射条件时才退回边缘复制。分块可降低显存需求，但不是无缝质量保证。
- **复现**：种子、模型 SHA256、输入 SHA256、尺寸、分块数、设备、混合参数随报告导出。不同硬件或库版本可能存在数值差异。
- **隐私与存储**：图片不发往外部推理服务，上传文件的 EXIF 元数据不保留到处理后的 PNG。原始文件不会被覆盖。处理后的输入、结果和报告保存在本工程 `runtime/<随机任务ID>/`，该目录不提交到 GitHub。
- **缓存**：服务内存最多保留 8 条任务，完成记录到期 30 分钟后在后续 API 访问时清理，达到保留上限时可提前清理旧任务。服务重启后不会自动索引或删除旧 `runtime` 文件，因此停服后可以手动删除该项目的 `runtime` 目录释放空间。及时下载需要保留的结果。
- **运行范围**：默认只监听 `127.0.0.1`，具备本地账户与任务访问校验，尚无公网部署配置；适合本机学习和工程展示。
